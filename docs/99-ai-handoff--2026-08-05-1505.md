## Phase 8 decisions (all in docs now)

- **A shift-over acknowledgement covers both endings.** `TIME'S UP` for timer
  expiry, `SHIFT ENDED` for END SHIFT EARLY, plus the patients-seen count. It
  WAITS for the player rather than timing out; any tap, Enter, or Space
  dismisses it. It is an overlay (`state.overlay = "shift-over"`), not a
  fourth view, so doc 7's three-view model is untouched. Quitting shows
  nothing — a quit shift is never scored.
- **Shift Review is a printed discharge summary** that fits one screen with no
  scrolling. TREAT THE LOOK AS PROVISIONAL — see the backlog item about
  reshaping it as a supervisor's evaluation form, which would replace this
  CSS rather than extend it. The CONTENT is settled.
- **Patients Seen reuses the Chart's clipboard wholesale.** The header slot
  that carries the live clock during play carries `1 / 3` here. There is no
  name banner — the chart's own nameplate already gives the name, so a banner
  only repeated it.
- **Navigation is fixed arrowheads beside the patient photo**, in the blank
  margin the 74%-wide scene already leaves. They are children of the
  clipboard, NOT of `.chart-scroll`, which is what makes them stay put while
  the paper scrolls; they cost no layout width. John rejected an earlier
  full-height rail version as taking too much space.
- **Scroll position carries between patients** as a proportion of scrollable
  height, so a player can walk everyone's ANSWER section without scrolling
  down each time. This REVERSES the old "resets to top" rule. Opening still
  starts at the top (the previous chart is empty, so the fraction is 0).
- **The nameplate is pinned** to the top of the scrolling area — in the review
  browser AND the Chart overlay during play.
- **The outcome shows twice**: a mark beside the chosen room in the Answer
  section, and a badge at 2x that size in the patient photo's bottom-right
  corner. Both use the in-game glyphs (green check / amber triangle / red
  cross). The badge sits on a pale disc so it reads over any portrait.
- **No photo zoom in the review chart** (John): zoom belongs to play, where
  the player is still reading evidence.
- **`answer.otherAcceptableRooms` is dead data** — null for all 160 patients,
  read by nothing. The full-credit set is DERIVED by `fullCreditRoomKeys`
  (Psych/Discharge also accept their underlying `esi-N`). The review chart
  calls that function so display and scoring cannot drift. Doc 5 corrected.

## Backlog (John's items first)

- **RUSH must never leave an empty waiting room (John, 2026-08-05)**: if the
  player clears the queue in RUSH, insert a new patient IMMEDIATELY rather
  than making them wait out the arrival interval. At least one patient should
  always be waiting. NOTE THE DOC CONFLICTS before building: doc 9's Phase 4
  gate currently states "RUSH selection does not refill", and doc 8's arrival
  algorithm needs the rule added. Decisions still to make: does the emergency
  refill doink? (doc 4 says every successful runtime insertion doinks, so
  presumably yes); does it reset or delay the base arrival interval walk? (it
  should NOT — the shrinking schedule is the mode's pressure curve); and does
  it count toward the Left Waiting penalty at shift end? (presumably yes).
  Rebuild the arrivals harness expectations afterward.

- **Review the last shift from ER ENTRANCE (John, 2026-08-05)**: HOME should
  offer a way back into the most recently completed or early-ended shift's
  SHIFT REVIEW. This is NOT Resume Shift — the shift is over and unplayable;
  it only reopens its results. WHAT THIS COSTS: `resetToLobby` in game.js
  currently wipes the ledger, queue, and deck, so the results are gone the
  moment the player leaves review. Implementing this means keeping a
  `lastCompletedShift` snapshot (the ledger records plus mode, difficulty,
  player, timestamps, elapsed, and the final left-waiting count) OUTSIDE the
  live shift state. Doc 9's Phase 8 line "Return to ER Entrance clears
  completed runtime state" needs amending to except that snapshot. Quit This
  Shift must still leave NOTHING reviewable. Phase 9 persistence should then
  carry the snapshot across a refresh.

- **Make the shift report feel like a real supervisor evaluation (John,
  2026-08-05)**: the printed-summary treatment is clean but generic. John
  wants it to read like the form an attending fills out on a resident —
  possibly returning to the clipboard motif, with grunge (coffee ring, toner
  streaks, a rubber stamp). Real-world models to borrow from: the Mini-CEX
  (one observed encounter, 1-9 ratings — closest to triageRush's unit of
  play), the end-of-rotation evaluation (Likert grid rating performance
  against EXPECTED LEVEL OF TRAINING, narrative strengths/improvement boxes,
  overall grade — closest to a shift), and ACGME Milestones / EPAs (rated by
  how much supervision the learner still needs). Borrowable conventions: a
  form number and revision date in a corner ("FORM ED-7 REV 08/26"),
  EVALUATOR and LEVEL OF TRAINING fields, a "below / meets / exceeds
  expectations" global rating derived from the score, a COMMENTS box written
  from the player's actual pattern (e.g. consistent under-triage), and a
  signature line. The player-title setting already carries level of training.
  This would REPLACE styles.css section 9, not extend it. NOTE: rating
  against expected level (an Intern judged differently from an attending) is
  a lovely mechanic but a SCORING change, not a visual one — confirm with
  John before treating it as in scope.

- **Sound volume control (John, 2026-08-05, consider - NO decision yet)**: the
  clock ticks, doinks, and other game sounds are fixed-volume with no player
  control beyond the on/off toggles. John wants some way to adjust — possibly
  a three-way OFF / QUIET / LOUD switch, possibly per-sound-family control,
  possibly a slider. The open question is the control's shape. The plumbing is
  friendly: every entry in app.js's `SOUND_REGISTRY` is `{enabled, play}` and
  each `play` builds its own Web Audio gain, so a global multiplier or a
  per-entry volume field is a small change. Must reconcile with the existing
  three toggles (GLOBAL, GAME SOUNDS, MUSIC) plus the in-game mute, and be
  persisted with the other settings in Phase 9.

- **Ambient ER soundscape (John, 2026-08-05, consider - NO decision yet)**: add
  background atmosphere — an ambulance siren arriving, a PA page ("Paging
  Doctor ..."), gurney wheels, distant chatter. Open questions: random

- **Music options beyond the single stream (John, 2026-08-05, consider)**:
  John asked for "Classical KING FM as a music option". NOTE: KING-FM is
  ALREADY the implemented music source — `ASSETS.music.kingFmStreamUrl`,
  played by `syncMusicPlayback`, governed by the MUSIC toggle. So this reads
  as making music a CHOICE rather than one hardwired stream: a picker offering
  KING-FM plus other stations or local tracks, with OFF still available. Needs
  a decision on what the other options are, where the picker lives, and how a
  failed stream falls back (today a failure switches MUSIC off and says so).
  Confirm the intent with John before building.

- **Lo-fi "hospital PA" music filter (John, 2026-08-05, consider - NO decision
  yet)**: run the music through a filter chain so it sounds like it is leaking
  from a waiting-room ceiling speaker rather than playing vibrant. Web Audio
  recipe: `createMediaElementSource(musicElement)` -> highpass ~400 Hz ->
  lowpass ~3.5 kHz -> a peaking boost around 1-2 kHz -> optional WaveShaper
  for grit -> gain -> destination. Two or three tunable numbers; easy to
  expose later as a CLEAN / LO-FI switch.

  CORS IS VERIFIED OK (checked 2026-08-05). The StreamGuys/Icecast endpoint
  answers with `Access-Control-Allow-Origin: *` plus
  `Access-Control-Allow-Methods: GET, OPTIONS, HEAD`, so the stream may
  legally feed a Web Audio graph. This was the one thing that could have
  killed the idea — routing a cross-origin `<audio>` element through Web Audio
  requires permissive CORS AND `musicElement.crossOrigin = "anonymous"`;
  without them the graph outputs SILENCE with no error, a confusing bug to
  meet cold. Do not skip setting `crossOrigin`, and set it BEFORE `src`.
  Remaining risk: adding `crossOrigin` changes a currently working playback
  path, so re-test plain playback (desktop + iPhone) alongside the filtered
  sound. If a future stream swap loses the CORS header the same silence trap
  returns. The standing fallback is locally hosted tracks filtered OFFLINE,
  which side-steps CORS entirely and pairs with the music-options item (a
  static GitHub Pages host cannot proxy, so proxying is never an option).
