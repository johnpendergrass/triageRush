## Important implementation contracts

- Use one serializable state tree and one-time effect queue.
- Derive totals from an ordered result ledger rather than mutating counters.
- Replace a patient's ledger record atomically on reassignment.
- Use an injected monotonic clock and random source for deterministic tests.
- Use one 250ms logical scheduler for clocks, cues, arrivals, and the 250ms
  second member of a RUSH burst.
- Emit doink only from successful queue insertion.
- Use one detailed-chart component for active Coach and Patients Seen review.
- Use one 9:16 view system with no wide-screen multi-page arrangement.
